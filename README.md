# Paper Radar

예방의학 · 응급의학 분야에서 최근 6개월 이내 발표된 논문 중 "핫한" 논문을 추적하는
개인용 정적 대시보드입니다. 서버가 필요 없습니다.

## 점수 산정 방식

의학 논문은 출간 직후 인용수가 거의 쌓이지 않기 때문에, 인용 지표만으로는
"최근 화제작"을 가려내기 어렵습니다. 그래서 세 가지 지표를 정규화해 합산합니다.

| 지표 | 비중 | 설명 |
|---|---|---|
| Altmetric 주목도 | 기본점의 50% | 언론·SNS·블로그 등에서의 언급도 |
| 인용수 | 기본점의 30% | 현재까지의 피인용 수 (iCite 기준) |
| Impact Factor | 기본점의 20% | 그 저널의 실제 JCR Impact Factor (`IMPACT_FACTORS`에서 관리, 로그 스케일 정규화) |
| **현재 호(issue) 게재** | **가산점 +10** | 그 저널의 가장 최근 정식 호에 배정된 논문이면 가산. 이미 편집진이 골라 실은 논문이라는 뜻이라 강한 신호로 별도 취급 |

기본점(위 세 지표 조합)은 90점 만점이고, 현재 호 가산점 10점을 더해 최종
`hot_score`가 최대 100점이 됩니다. "현재 호"인지는 PubMed의 volume/issue
정보로 판별합니다 — issue 번호가 없거나 "ahead of print" 상태면 아직 정식
호에 배정되지 않은 것으로 보고, 같은 저널 안에서 issue가 배정된 논문 중
가장 최근 날짜를 기준으로 45일 이내인 논문에 가산점을 줍니다
(`collect.py`의 `CURRENT_ISSUE_WINDOW_DAYS`로 조정 가능).

## 수집 기간: 최근 3년, 구간별로 고르게

`RELDATE_DAYS`(기본 1095일 ≈ 3년)가 전체 수집 기간입니다. 예방의학/응급의학
같은 넓은 검색어는 3년이면 수만 건이 나오기 때문에, 단순히 "최신순 N건"만
가져오면 기간을 아무리 늘려도 실제로는 최근 한두 달치만 긁히는 편향이
생깁니다 (예전에 6개월 창에서 겪었던 문제와 같은 원인).

그래서 전체 3년을 `BUCKET_COUNT`(기본 6)개 구간(구간당 약 6개월)으로 쪼개서,
구간마다 `MAX_PER_BUCKET`(기본 50)건씩 고르게 수집합니다. 이러면 2023년
논문도, 2026년 논문도 똑같이 점수 비교 대상에 들어옵니다. 분야당 총 수집
풀은 `BUCKET_COUNT × MAX_PER_BUCKET`(기본 300건)로, 이전 6개월 버전과
비슷한 규모라 수집 시간도 비슷합니다.

화면에는 이 풀 중 저널당 상위 `TOP_PAPERS_PER_JOURNAL`(기본 10)편, 분야당
상위 `TOP_JOURNALS_PER_FIELD`(기본 25)개 저널까지만 보여줘서, 정말
"핫한 것만" 추려지도록 필터링합니다. 저널 카드에는 "전체 N건 중 상위 M건"
형태로 몇 편 중에서 추려졌는지도 함께 표시됩니다.

**참고**: 3년이면 오래된 논문은 인용수가 꽤 쌓여있을 수 있어서, 인용
지표(현재 30% 비중)가 6개월 창일 때보다 더 믿을 만한 신호가 됩니다. 반대로
Altmetric 주목도(50% 비중)는 갓 나온 화제작에 더 잘 반응하는 지표라, 오래된
논문에는 상대적으로 낮게 나올 수 있어요. 이 비중이 3년 창에서도 원하시는
그림과 맞는지 한번 살펴보시고, 조정하고 싶으시면 `collect_field()`의
가중치(`0.5 * a_n + 0.3 * c_n + 0.2 * i_n`)를 바꿔달라고 말씀해주세요.

기간을 더 늘리거나 줄이고 싶으면 `RELDATE_DAYS`를, 구간 수는 `BUCKET_COUNT`를,
구간당 수집량은 `MAX_PER_BUCKET`을 조정하면 됩니다. 저장소가 Public이면
GitHub Actions 실행 시간은 무료·무제한이라 수집 시간이 길어져도(현재 설정
기준 분야당 약 20~30분) 비용 걱정은 없습니다.

## 화면 구조

**둥글둥글한 톤 + 왼쪽 사이드바 → 오른쪽 상세 리스트** 구조입니다.

- 히어로 영역에 "최신 트렌드 논문" 제목, 파랑-보라 그라데이션.
- 상단 컨트롤: 분야 탭(전체/예방의학/응급의학), 검색창, **정렬 드롭다운**
  (핫점수순 / IF순 / 인용수순 / 최신순), **"Q1만 보기" 토글**.
- **연도별 트렌드 라인 그래프**: 최근 3~4개 연도에 걸쳐, 그 분야에서 가장
  영향력 있는 주제 상위 6개가 해마다 얼마나 화제였는지 선 그래프로 보여줍니다.
  (걸러지지 않은 전체 수집 풀 기준으로 계산해서 연도별 그림이 왜곡되지
  않게 했습니다.)
- **핫토픽 버블 차트**: 막대그래프 대신, 점수가 클수록 큰 원으로 표시되는
  버블 클라우드입니다(현재 3~4개년 전체 기준). **원을 클릭하면** 그 주제
  (구절)가 제목에 들어간 논문만 오른쪽에 걸러서 보여줍니다. 다시 클릭하면
  필터가 풀립니다.
- 왼쪽 사이드바: 발행월별로 묶이고, 펼치면 그 안에서 SCIE / ESCI / 미상
  등급 버튼이 나옵니다. 클릭하면 오른쪽에 그 조합의 논문이 나열됩니다.
- 각 논문 카드: 원문 제목 + **한글 번역 제목**, 분야·등급·**JCR 사분위
  (Q1~Q4)**·IF·현재 호·인용수 태그, 점수 막대그래프, **"초록 보기"**를
  누르면 펼쳐지는 Abstract.
- 검색창에 뭔가 입력하면 사이드바/버블 필터와 무관하게 검색 결과만 보여줍니다.
- "Q1만 보기"를 켜면 사이드바 목록·주제 필터·검색 결과 어디서든 JCR Q1
  저널 논문만 남습니다.

### JCR 사분위(Q1~Q4)에 대한 참고사항

`JOURNAL_QUARTILE` 딕셔너리에 확인된 저널의 사분위를 채워뒀습니다. 다만:

- JCR은 저널 하나가 여러 카테고리에 속할 수 있고, 카테고리마다 사분위가
  다를 수 있습니다. 여기서는 논문 분야와 더 관련 있는 카테고리 쪽 사분위
  하나만 골라 넣었습니다.
- JCR은 매년 6월에 갱신되므로, 정확한 최신 값은
  [Clarivate JCR](https://clarivate.com/academia-government/scientific-and-academic-research/research-funding-analytics/journal-citation-reports/)에서
  직접 확인해 `JOURNAL_QUARTILE`을 갱신하는 걸 추천합니다.
- 목록에 없는 저널은 `DEFAULT_QUARTILE`(기본 "미상")이 적용됩니다.

### 한글 제목 번역 / Abstract에 대한 참고사항

- 번역은 **무료 MyMemory API**를 씁니다. 키 발급 없이 쓸 수 있지만 하루
  무료 한도가 작아서(약 5,000단어/일), 논문 수가 많으면 며칠 걸쳐 한도가
  찰 수 있습니다. `collect.py` 상단의 `MYMEMORY_EMAIL`에 본인 이메일을
  넣으면 하루 한도가 50,000단어로 늘어납니다 (별도 가입 없이 그냥 파라미터로
  붙이는 것뿐입니다).
- 번역/초록 조회는 **이미 걸러진(저널당 상위 10편, 분야당 상위 25개 저널)
  논문에만** 적용됩니다. 그래서 전체 600건이 아니라 최대 250건 정도만
  대상이 되어 시간이 크게 늘지 않습니다.
- Abstract은 PubMed의 `efetch`로 따로 가져옵니다. 사설·서신·일부 증례보고처럼
  원래 초록이 없는 논문은 "초록 없음"으로 표시됩니다.
- 핫토픽 버블의 클릭-필터는 `hot_topics`의 `pmids` 목록으로 매칭합니다.
  이 목록은 (전체 수집 풀이 아니라) 화면에 실제로 보이는 논문들만 대상으로
  계산되므로, 주제를 클릭했을 때 항상 화면에 있는 논문과 연결됩니다.

### 등급(SCIE/ESCI) 필터

사이드바의 등급 버튼은 SCIE(Science Citation Index Expanded) /
ESCI(Emerging Sources Citation Index) / 미상으로 나뉩니다. 이 색인 등급은
Clarivate의 Web of Science 기준으로, 제가 직접 확인한 저널만
`JOURNAL_INDEX` 딕셔너리에 채워뒀고 나머지는 정직하게 "미상"으로 남겨뒀습니다.
(Scopus 등재 여부는 Elsevier의 별도 유료 데이터라 무료 API로 자동 판별할
방법이 없어서 포함하지 않았습니다 — 필요하시면 `JOURNAL_INDEX`에 직접
"SCOPUS" 같은 값을 추가해서 쓰실 수 있게 구조는 열어뒀습니다.)

`IMPACT_FACTORS`, `JOURNAL_INDEX` 딕셔너리는 2024/2025년 JCR 기준
대략값을 미리 넣어뒀지만, 매년 6월 JCR이 갱신되므로 정확한 최신 값으로
직접 업데이트하시는 걸 추천합니다. 목록에 없는 저널은 IF는
`DEFAULT_IMPACT_FACTOR`(기본 1.5), 등급은 `DEFAULT_INDEX_TYPE`(기본
"미상")이 적용됩니다.

## 빠르게 한 번 써보기 (자동화 없이)

1. Python 환경에서:
   ```bash
   pip install requests
   python collect.py
   ```
   PubMed → iCite → Altmetric → (걸러진 논문만) 번역·초록 순으로 조회하므로
   시간이 꽤 걸립니다 (현재 설정 기준 20~30분 정도).
2. `data/papers.json`이 생성되면, 같은 폴더에서 로컬 서버를 하나 띄워 index.html을
   엽니다. (브라우저가 `file://`에서는 fetch를 막는 경우가 많아 간단한 서버가
   필요합니다.)
   ```bash
   python -m http.server 8000
   ```
   그리고 브라우저에서 `http://localhost:8000` 접속.
3. 갱신하고 싶을 때마다 `python collect.py`를 다시 실행하면 됩니다.

## 완전 자동화 (매일 무인 갱신, 무료)

서버 없이 완전히 자동으로 매일 갱신되게 하려면 GitHub만 있으면 됩니다.

1. 이 폴더를 새 GitHub 저장소에 올립니다.
2. 저장소의 **Settings → Pages**에서 `main` 브랜치, 루트(`/`)를 소스로 지정해
   GitHub Pages를 켭니다. → `https://<사용자명>.github.io/<저장소명>/`에서
   바로 접속 가능.
3. `.github/workflows/update.yml`이 이미 포함되어 있어서, 별도 설정 없이
   매일 UTC 20:00(한국시간 새벽 5시)에 자동으로 `collect.py`를 실행하고
   `data/papers.json`을 커밋합니다.
4. **Actions** 탭에서 `Update paper data` 워크플로우를 수동으로 한 번
   실행(`Run workflow`)해서 첫 데이터를 채워주세요.

이후로는 매일 아침 접속할 때마다 최신 데이터가 반영되어 있습니다.

## 커스터마이징 아이디어

- `RELDATE_DAYS`를 바꿔 "최근 N일" 범위를 조정
- `IMPACT_FACTORS`, `JOURNAL_INDEX`에 자주 보는 저널의 실제 IF·등급을 추가/갱신
- `STOPWORDS`에 단어를 추가하면 핫토픽 키워드에서 그 단어를 제외할 수 있습니다
- Altmetric API는 무료 조회에 속도 제한이 있어 논문 수가 많으면 시간이 걸립니다.
  `MAX_PER_FIELD`를 낮추면 더 빨리 끝납니다.
- 분야를 더 추가하고 싶다면 `FIELDS` 딕셔너리에 PubMed MeSH 쿼리를 하나 더
  넣으면 됩니다.
